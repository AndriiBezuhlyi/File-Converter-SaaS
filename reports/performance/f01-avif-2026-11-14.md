# F01 — AVIF performance optimization

Date: 2026-11-14 (Europe/Paris). Base: fetched `origin/main`, `8126416`.
Branch: `perf/f01-avif`. Scope: AVIF encoder effort only; no dependency,
quality-setting, contract, direction, concurrency, timeout or sandbox changes.

## Decision

Use Sharp AVIF `{ quality: 50, effort: 2, bitdepth: 8 }`, replacing effort 4.
Effort 2 resolves the original CPU-budget failure with substantial headroom,
while retaining fine lines/text better than efforts 0/1 in the graphics fixture.
The inspected photo and graphics crops and composited alpha gradient showed no
material visual regression versus effort 4. Outputs are lossy and not identical.
The photo grows 8.1%, graphics 4.3%, and alpha fixture 10.7%; this is a measured
compression trade-off, not a change to the quality setting. Effort 2 has the best
source PSNR among 0/1/2 on noise, graphics, alpha and oriented fixtures; codec
effort is not a monotonic quality or output-size control on every image.

Production change: one AVIF option in `engine-process.ts`. The new independent
`avif-performance.linux.mjs` regression uses the original fixture and production
`ConversionEngine`, including all existing guards. `test:engine:linux` includes
the regression and runs test files sequentially to avoid competing encoders.
Existing tests and implementation/improvement plans are unchanged.

Sharp option reference, checked via Context7:
[Sharp output API](https://sharp.pixelplumbing.com/api-output/#avif).

## Evidence and method

Reused the original audit's `avif-diagnostic.mjs`, `avif-diagnostic.jsonl`,
`engine-probe.mjs`, and `engine-measurements.jsonl` in
`../Converter-artifacts/webperf-audit-20261113/`. No full audit was repeated.
The audit recorded exit 137, 50,502 ms wall, 50,450 ms cgroup CPU, no output and
zero OOM events. Current reproduction: exit 137, 52,685 ms wall, 52,493 ms CPU,
zero output. This is a failed baseline, not a completed effort-4 encode time.

Local Docker Desktop/WSL2, Node 24.22.3, Sharp 0.35.5, libvips 8.18.7,
libaom 3.15.1, libheif 1.23.5. Reused local `flux-ci-worker:local` image
`508aba55207e`, mounting current compiled source read-only. Each conversion uses
the unchanged production `sandboxArguments`: Bubblewrap namespaces, cleared
environment, read-only mounts, 128 MiB work tmpfs, prlimit 50 CPU seconds/2 GiB
address space, jitless Node/128 MiB heap, Sharp concurrency 1/cache disabled,
45-second image timeout and 60-second process-tree deadline. Container: init,
1 CPU, 1 GiB RAM, 128 PIDs, read-only root, 256 MiB /tmp, dropped capabilities,
no-new-privileges, repository seccomp; benchmark has no network or credentials.
No AppArmor/seccomp/kernel policy changes were made.

The harness substitutes only the read-only engine entry point to compare effort
4/0/1/2. Each variant has otherwise identical code and encoder options. Runs are
sequential; successful cases repeat three times, failing baseline stops after
one. Wall time measures sandbox start through close; CPU is the container
`cpu.stat` delta, including harness sampling overhead. Quality is measured after
the timer, against auto-oriented source pixels composited on white. PSNR uses
RGB MSE. `blockSsim` in raw data is a simple contiguous 64-RGB-pixel block proxy,
not standard spatial-window SSIM, perceptual equivalence or a release threshold.

Fixtures:

- `audit-6mp`: original xorshift seed 123456789, 3000×2000 RGB noise, JPEG quality
  90, exactly 4,947,939 bytes. The committed regression retains the generator.
- `photo`: natural landscape, 3000×4500, 2,251,444 bytes, downloaded once from
  [Unsplash fixture](https://images.unsplash.com/photo-1500530855697-b586d89ba3ee?w=3000&q=90&fit=crop).
  SHA-256: `ae9f8173d9782ea32f3b4d551cca62a8ee7a679e1a7069a543808c56852eaf34`.
- `complex`: 1200×800 PNG, 379,271 bytes; gradient, 150 intersecting circles and
  small numbered text. This deliberately exposes halos and fine-detail loss.
- `alpha`: 1000×700 PNG, 58,979 bytes; transparent circle and varying opacity.
- `one-pixel`: 1×1 RGBA PNG; tiny-image and semi-transparent edge case.
- `oriented`: photo resized to 640 pixels wide, JPEG quality 90 with EXIF
  orientation 6; output must be 960×640 with orientation metadata removed.

Exact fixture recipes, scripts, raw measurements, AVIF outputs and inspected
`photo-comparison.png`/`detail-comparison.png` remain in the task worktree's
`.cache/tasks/f01-avif/`. These local diagnostics are intentionally untracked.

runs passed. The original failed terminal outcome at 52.7 s is replaced by a

effort-4 noise encode was obtained). Photo wall/CPU fell 83.4%/83.5%, about 6×

Photo PSNR changes by -0.381 dB; graphics by -1.779 dB. Effort-2 block proxies
are 0.974157 photo, 0.998759 graphics, 0.999518 alpha. Alpha channels remain
present, spanning 0–255. These proxies and the visual inspection support the
choice on these fixtures, not a universal perceptual-quality guarantee.

The repeated harness's peak container memory spans approximately 454–1009 MiB
and includes retained fixtures, decoded reference/output buffers and tmpfs.
Its samples share a process, so those peaks must not be interpreted as isolated
encoder RSS or evidence of memory reduction. Separate fresh-container resource
measurements are recorded below.

timing. They do not construct quality-reference images. Memory is sampled

## Limitations and retained work

Finite local lab corpus, one natural photo, three timing repetitions per
successful case; not production load, real-user p95, cross-host throughput or a
guarantee for every image up to the supported pixel/byte limits. Very large or
adversarial inputs can still exhaust the unchanged budgets and must fail safely.
Larger AVIFs can increase transfer/storage cost. Alpha is lossy; no exact alpha
preservation claim is made. Memory is not assumed to improve merely because
CPU improves. Fontconfig emitted cache warnings in the read-only test runtime;
graphics rendered and tests passed without relaxing filesystem restrictions.

No frontend code changed; no browser UI, complete unrelated test suite, hosted
CI or production deployment verification is claimed. No push, PR creation,
merge or deployment. The dedicated worktree and local diagnostic directory
retain unique work and must be preserved for review.
