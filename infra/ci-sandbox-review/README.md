### Narrowed permissions for approval

The previous candidate's global `file`, `capability`, `umount` and cross-product bind permission are removed. Specific read/map/exec and scratch write rules replace them, including Docker's injected init executable for the existing `--init` process-reaping boundary. Broad `/oldroot/** r` and `/tmp/** rwkl` have also been removed after independent review. Six named namespace-local capability checks cover mount/pivot, chroot, UID/GID changes, capability dropping and loopback configuration; they do **not** grant an outer capability. The outer Docker capability sets remain zero. A successful runtime/audit is still needed to establish sufficiency and minimality; no such result is claimed.

The profile is a static final candidate for this single experiment, **not proven minimal or runtime-compatible**. Any missing permission ends the experiment. A subsequent policy change needs a new diff, hash and approval. Existing file/proc/sys denials, seccomp, cgroup bounds, read-only root, NoNewPrivs and both network isolation layers remain intact.

The capability allowlist is explicit: `sys_admin` covers namespace-local mounts/pivots; `sys_chroot` covers root setup; `setuid` and `setgid` cover namespace identity setup/drop; `setpcap` covers capability dropping; `net_admin` covers loopback setup in the new network namespace. None is a Docker `--cap-add`. Read/map rules support ELF/native modules; inherited exec (`ix`) never changes the AppArmor profile; scratch write/lock/link rules support staging and LibreOffice's temporary files only. The existing `attach_disconnected`/`mediate_deleted` flags and proc/sys write denials retain the earlier baseline behavior. These are reasoned static requirements, not runtime proof that every listed permission is exercised.

### Independent review follow-up

- `/oldroot` is bwrap's temporary view of the container root during mount setup, not the host root. General recursive reads are unnecessary: the candidate now names runtime libraries, selected configuration, six engine modules, saved-proc-fd metadata, devices and synthetic input prefixes. `/oldroot/etc/passwd` and unrelated old-root paths are not granted by these rules.
- General `/tmp` writes are unnecessary: unchanged tests need `engine-test-*`, `isolation-test-*`, `worker-crash-*`; extra probes use `flux-probe-*`. Only those prefixes and bwrap's `newroot`/`oldroot` staging directories remain writable there. An additional outer-container negative probe requires an unrelated `flux-unapproved-*` write to fail with EACCES/EPERM. LibreOffice's per-attempt temporary files resolve to `/work/tmp`, so `/work` remains the bounded writable sandbox workspace. The trusted orchestrator can manage multiple test attempts; these permissions are not a claim that it is isolated from its own scratch files.
- `umount /` remains reasoned necessary for bwrap 0.8.0's second pivot: it keeps a descriptor to the former staging root, calls `pivot_root('.', '.')`, changes back through that descriptor and detaches the old mount. AppArmor path permission alone is **not** proof of host isolation. Safety also requires Docker's separate mount namespace, zero outer caps, no host namespace descriptors or host proc mount, bwrap's fresh mount/user namespaces and one-way/private propagation. The orchestration script now snapshots the controller mount namespace/root mount and checks them after execution; outer probes require a different namespace from the controller and no shared mounts. No live host-isolation result is claimed yet.
- Source inspection also identified the omitted `rprivate` operation on `/oldroot` before its first detach. Only that exact propagation rule is added; this is an explicitly reviewed static change, not an automatic response to a failed runtime probe.
- Debugger attach/trace was not justified. `ptrace (trace,tracedby,read,readby)` becomes **`ptrace (read,readby)`** for bwrap/proc namespace/fd metadata and original crash-test process inspection. No `CAP_SYS_PTRACE` is added. This permits kernel ptrace-mode read checks, not debugger attach. A shared AppArmor label is not an attempt identity boundary; separate PID/user/mount namespaces provide that boundary.
- The new negative probe keeps attempt B alive, identifies it from the trusted parent, then requires attempt A to see neither B's input directory nor PID/proc-memory path and to receive `ESRCH` for signal-0 lookup. The parent verifies B is still alive afterward; cleanup kills only B's owned process group. This exercises PID/filesystem/proc-memory separation, **not an actual ptrace attach syscall**. The four original tests remain unchanged.
